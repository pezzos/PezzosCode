# Global Architecture / Design

> Machine-managed by `tools/pc-prepare-features`. Edit PRD/context and rerun instead of hand-editing this file.

**Last Updated:** 2026-02-16

## System architecture

```text
Human PO
  -> make prepare-features
     -> docs/01-product/design.md (Architect)
     -> docs/01-product/ux-ui.md (UX)
     -> docs/02-features/feature-order.json (Dependency Planner)
     -> tools/prd-to-features (Feature Generation)
  -> make review-features (Security + Product review)
  -> make feature F=<feature-id> (execution loop)
```

## Module boundaries

| Module                | Responsibility                                 | Boundaries                                                           |
| --------------------- | ---------------------------------------------- | -------------------------------------------------------------------- |
| docs/00-context       | Product context and operating limits           | Input-only for preparation, not regenerated by tooling               |
| docs/01-product       | PRD + architecture/UX blueprints               | Global product blueprint consumed by generation and reviews          |
| docs/02-features      | Feature-level implementation specs/tasks/tests | Generated/updated in dependency order, never delete existing folders |
| tools/prd-to-features | Feature docs hydrator                          | Consumes PRD + ordered plan and updates in place                     |
| tools/pc-feature      | Work-item execution runtime                    | Unchanged by prepare/review workflows                                |

## Infra considerations

- Local-only CLI execution on macOS with git-backed repository state.
- No cloud services, no background daemons, no remote state storage.
- Structured logs and offloaded command output remain mandatory for noisy steps.
- Existing command authority remains: only the human PO triggers orchestrator commands.

## Design constraints

- Local CLI tool only; manual execution, no daemon or cron.
- Target platform is macOS (primary); no Windows support.
- Bootstraps new projects or updates existing repos with templates.
- Enables AI-driven execution of features/tickets with minimal manual setup.
- Serves one user only and is intentionally tuned to that user's tools/habits.
- Git is built into the workflow; tools operate inside repo boundaries.
- Non-goal: Automatic background sync or scheduled runs.
- Non-goal: Cloud services, remote state, or multi-user collaboration.
- Non-goal: Generic support for multiple development styles or broad team configurability.
- Non-goal: UI (web or desktop) in this project.

## Build strategy

- 1. Update context docs when assumptions or constraints change.
- 2. Refresh PRD from context before preparation.
- 3. Run `make prepare-features` to regenerate design/ux/order artifacts and feature docs.
- 4. Run `make review-features` to inject security/product findings before execution.
- 5. Execute work items with `make feature F=<feature-id>` using existing runtime gates.
- 6. Maintain operating model guardrails: User runs the CLI to bootstrap or update a project, then uses CLI commands to drive AI execution.
